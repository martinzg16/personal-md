A file that fills in forms

Job applications, government surveys and personal-info forms ask the same questions forever. personal-md keeps the answers in one markdown file you own, recognises a question it has seen before in either language, and drafts genuinely new ones in your own voice from what you have already written.

The panel is your file, projected onto someone else's form

Every autofill extension shows you a list of the page's fields. This one inverts that. Each row leads with what you wrote and where it came from, naming the host field only as the destination — because the question you are actually answering is "is this the right answer of mine", not "what does this form call this box".

A wrong autofill is worse than no autofill, because it gets submitted.

So nothing fills without a click, every value shows its source, a fill that fails says so and names the cause, and undo is always one click away — scoped to exactly what it undid.

Sensitive facts stay useful without being sent

A Spanish government form needs your NIF. The drafting engine never does. Short fields are matched deterministically and locally, so the values you would never paste into a chat window are exactly the values that require no network at all. An egress allowlist decides what may reach a prompt, and it fails closed: a key nobody has explicitly allowed is refused.

The guard scans the fully assembled prompt — including your own stored answers, which may contain a tax ID you typed years ago — and throws rather than redacting. A silent redaction would teach you the guard does not apply.

Grounding outranks fluency

A draft cites its sources before a word of it appears, so you can tell immediately whether the question was understood. Every concrete claim — employer, title, team size, metric — has to appear in something you actually wrote. Anything missing becomes an explicit gap to fill rather than a plausible invention.

Plausibility is not evidence.

Nothing is stored silently

The naive reading of that is a prompt per field, which is unusable on a thirty-field form. So the panel notices quietly while you fill, asks once at the end about everything together, and writes once. Values are editable in the panel, because the page is where a value came from — not the authority on what it means.

A value your file already holds is never offered. Confirming what you already know teaches nothing and trains you to click through without reading, which is how a confirmation step stops working.

What it refuses to do

  • —Open itselfDetection shows a pill with a count. Expanding is always your click.
  • —Appear on a bank or payment pageIt has nothing useful to contribute there, and a mistake is expensive.
  • —Touch a password, card number or CVVRefused at the classifier, refused again at the DOM, and never captured.
  • —Send a sensitive fact to a modelWithheld keys fill locally or not at all.
  • —Obey the pageField labels and questions are data. Text addressed to the model is flagged, not followed.
  • —Auto-submit anythingThere is no code path that clicks a submit button.

How it runs without an API key

Inference goes through the claude CLI on your own account, so there is no key to store and no per-token bill. A Chrome extension cannot spawn a process, so a small companion listens on 127.0.0.1 behind a generated token and owns the file on disk. That constraint turned out to be the feature: PERSONAL.md is a real file you can open in any editor, hand-edit mid-session, and diff.

Each call carries about 26,000 tokens of scaffolding, of which roughly 99.9% is a prompt-cache read — which is the only reason this route is affordable. A test pins it: if the cache read ever drops to zero, every call silently costs about ten times more.
